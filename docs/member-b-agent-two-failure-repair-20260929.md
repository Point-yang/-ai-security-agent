# B Agent 两条失败样例修复与审计

日期：2026-09-29。原始 v3 冻结题集及 21 行配对报告保持不变；本文件记录针对已知题的事后修复，不把事后复跑当成新留出集。

## 根因与修复

1. `fresh-patch-30202` 的首次检索确实找到了厂商与 GitHub 两个当前来源。Agent 选择 `compare_sources` 后，服务端补取第一份来源详情成功；第二份详情的 JSON 长度为 **9449 字符**，超过单次工具 **9000 字符**上限，返回 `output_budget_exceeded`。旧答案因而只有厂商的 `packages` 字段，无法完整回答“两家来源分别给出什么”。现在将每条详情片段上限设为 700 字符。相同评测库中，两份 `event_details` 都成功，两个来源的 `packages`、PR 17197 片段均进入已核验引用，仍处于六次工具调用与 24000 字符总预算内。
2. `fresh-summary-46570` 在旧 AI 预审中被判“答案引用 `[15]`，但只有 14 条引用”。复核原始 v3 报告和盲审题包后发现**两处都是 15 条引用**；第 15 条是厂商描述，明确包含前缀缓存机制和 TTFT。原始生成状态也是 `completed`，逐字引用校验通过。该“越界引用”是评审计数错误，不应作为 Agent 实现缺陷。事后复跑中模型仍曾出现一次新的 `invalid_citation`，说明引用格式波动真实存在；代码现在把错误细分为越界编号、非逐字 quote、结论自带编号等审计类型。
3. 当模型在双来源版本题中给出不合法引用时，Agent 现在只根据**已经完成当前原文校验**的两份标题、`packages` 字段和确切 PR 链接生成本地简明答案。必须具备两份来源的标题及版本字段；题目要求修复依据时，还必须两份来源都有 PR 片段。字段名 `first_patched_version` 与 `patched_versions` 原样保留。该路径标记为 `local_fallback=two_source_version_fields_v1`，仍记录云生成失败，不冒称模型生成成功。
