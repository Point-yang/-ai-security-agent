## 实现与边界

新增 `generation=agent`，可从工作台“有界 Agent 工具选择（实验）”或既有 `POST /api/v1/rag/answers` 请求使用。若指定持久会话，沿用同一 `conversation_id` 与 `request_id` 去重规则；模型选择、工具输入、失败代码、原文复验、生成和用量随 RagRun 及会话 hop 保存。页面直接列出选择摘要与工具步骤，并把显式资产比较结果作为本地可展开信息显示。

每轮只有一个 `AgentToolRuntime`。第一步让模型在固定 `retrieve` 契约内选择检索参数；随后根据当前检索结果，在 `event_details`、`compare_sources`、补充 `retrieve`、`verify_evidence` 和**有明确资产时才提供的** `asset_exposure` 中选择最多三步。混合模型不可用时，可以经过一轮明确的模型选择，改用词项检索。运行层始终固定用户选定的 formal/candidate 与 live/replay，显式事件 ID 作为检索边界，事件详情和比较目标须属于当前检索发现的对象。A 的每轮最多 6 次工具调用、15 秒软截止与 24000 字符累计输出上限仍生效；模型不能执行未列入契约的工具或任意代码。

规划请求从 `contracts()["tools"]` 生成候选定义，记录问题、候选工具、选中工具和不超过 220 字的动作摘要，不保留模型隐藏思考。第二步规划只收到公开来源标识及小段摘录；私有资产名称、组件明细、exposure 结果不送给云端规划或最终生成。模型只能填 `<selected_asset>` 占位符，服务端使用用户明确选择的资产 ID 后再执行本地只读工具。资产条件匹配不等于漏洞复现；跨源比较仍是未裁决的派生观察。

工具读取后，再对本轮将引用的每个当前 chunk 调用原有原文字节/指针/摘录校验；任何一个失败则整轮拒引。最终 DeepSeek 生成仍要求编号加逐字引用，格式或引用失败显示本地摘录并保留失败。规划出错或工具检索失败时会显式降到本地词项摘录，保留错误代码；不会自动重复云端请求。引用的字节一致性**不等于**模型中文概括的语义正确性，`semantic_support_verified=false`。

## 真实三模式对照与失败保留

[原始 12 题报告](member-b-agent-comparison-full.json)保持不改写；[事后七题复测](member-b-agent-comparison-recheck.json)及[补检索限制两题诊断](member-b-agent-comparison-recheck-v2.json)单独保存；[校正口径与结论](member-b-agent-comparison-analysis.json)明确将模型规划失败与实际执行的工具成功率分开，并修正原报告把有引用的本地词项降级误计为“未做字节检查”的分母错误。三批使用同一 3214 片段资料副本；该开发集此前已用于调参，不是独立隐藏金标。

“已执行工具 10/10 成功”只统计模型已经成功规划后的工具，**不能**掩盖 4 次规划失败。原始 Agent 还有一次生成引用不匹配，安全降级为本地摘录；一些无答案题没有进行模型调用。Agent 总 token 较少主要因为成功生成的题数少；按成功生成题摊销，Agent 为约 5364 token/题，普通 DeepSeek 为约 4167 token/题，不能称为成本优势。七题事后复测将规划完成提高到 14/14，但 Agent 成功生成仍为 4/7，普通 DeepSeek 在原配对数据中为 6/7；复测是看过失败后的诊断，不能并入原始留出成绩。复测中第二步模型主要选择再次检索，未证明多工具策略带来稳定增益。

针对重复补检索，现代码只在首轮检索稀疏时提供一次补检索，且对模型越界选择保留失败记录。该修改后的两题事后诊断虽都命中预设事件集合，但 **0/2 成功生成**：一题生成引用不匹配，另一题规划请求了未提供的工具而降级。它不是改善质量的证据，也不能回填原始 12 题表。

每题原文、工具决定、生成失败与耗时留在 JSON。自动引用哈希和逐字摘录通过不证明结论语义成立，因此正确性、语义引用支持、完整性与正式费用金额继续标 `null`。没有人工独立标注前，不报官方问答准确率或 Agent 得分提升。
