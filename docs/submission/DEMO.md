# 使用与答辩演示

从项目根目录按 README 启动后，打开 `http://127.0.0.1:8010/workspace`。网页必须通过服务访问，不能双击 HTML。可点击右上角“答辩模式”。

## 约6分钟演示主线

1. **情报与证据检索**：在“CVE/别名”填 `CVE-2026-73557`，点击查询。快照中保留 GitHub、NVD、vLLM 厂商三条记录。
2. **结构化富化**：打开 GitHub 记录，展示组件、受影响版本、修复版本和质量标记。
3. **原文与版本**：展开 `packages` 引用，展示 JSON 指针、版本、SHA-256 和完整原文。原文及历史修订已随包保留。
4. **来源复核与比较**：用同一 CVE 查询比较。GitHub 范围为 `>=0.21.0,<0.26.0`，NVD 为 `>=0.20.2rc0,<0.26.0`，厂商保存的范围为 `>=0.21.0`。解释来源表述差异，不擅自补全缺失上界。
5. **Agent 指挥中心**：点击“查看历史真实运行”，展示规划、研究、生成、核验及工具回执。它是2026-10-13保存的真实运行，当前不会调用模型；原实验仍有语义遗漏，不能说是现场新生成。
6. **运行审计与评测**：介绍持久会话和调用费用。提交包已排除私人会话，首次进入会话页为空；新建任务后才会产生记录。已有评测依据见 `evidence/` 和评测说明。

来源监测页在刚解压的包中显示未启动或待采集是正常的：为了不把原机器进程状态当作当前状态，导出时清除了监测心跳与运行日志。需要演示持续采集时，在另一终端执行 `python -m zhidu monitor --sync-semantic`，并等待真实结果。

## 新运行一次多角色问答

在 `.env` 设置管理员密钥与模型密钥，重启服务。网页授权区填写管理员密钥，新建会话，执行策略选“多角色规划、补查与引用核验（实验）”，检索选混合。

建议问题：

> 比较 CVE-2026-73557 在 GitHub 与 NVD 中的受影响版本范围，指出上下界差异，并逐项给出原文引用。

追问：

> 哪个来源明确给出了首次修复版本？请引用原始字段，不推测未写明的信息。

任务返回后展开“对应原文”“问题完整性与研究记录”和“完整执行审计JSON”。如果是 partial，就说明缺失项；如果超时，保留原请求，切换历史回放，不连续提交造成重复费用。

## 可选资产分支

包内不带真实资产。可在解压后的演示副本导入明确虚构的 SBOM：

```sh
.venv/bin/python -m zhidu asset-import examples/submission-demo-sbom.json --asset-name '虚构演示资产 vLLM 0.22.0' --environment demo
```

打开 `/assets`，展示对应来源条件、组件版本和证据。此操作会写入演示副本；它表示条件匹配，不表示漏洞已被利用。验证交付文件哈希应在导入或采集之前进行。
