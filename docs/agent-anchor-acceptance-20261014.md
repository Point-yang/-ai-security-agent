# 正文 ID 核验协议验收

核验日期：2026-10-14。正文 ID 协议已接入产品，最终实现为 `langgraph-source-team-v9`，共同回答合同仍为 `source-answer-v10`。756 项 Python 测试、47 项前端测试及 Ruff 通过。本轮新增一次真实核验请求，随后使用同一次返回做零调用复验；没有重新规划、检索或生成原候选。

## 改动与结果

原接口要求核验器重新抄写中文答案正文，模型曾把英文来源引文写入该字段，导致整轮降级。现在服务器为当前候选的每条完整结论生成 `ans_` ID，为该句实际引用生成独立的 `src_` ID。核验器只能用当前 `ans_` ID 标记任务与子项覆盖，服务器回填真实正文和位置。

ID 绑定原问题、请求范围、完整候选与自身实际引文及出处。答案、引用或请求范围变化后，旧 ID 会被拒绝；未知 ID、来源 ID、重复 ID、子项引用任务之外的 ID 均拒绝。删除不支持的结论后，账本保留候选 ID，并映射至最终结论索引。顶层索引表不重复正文或引文全文。

该协议保证定位一致性。合法 ID 不能证明子项语义已覆盖；句子支持、原问题遗漏、`any/each/compare` 来源要求仍分别核验。另一来源没有重复说明，不会自动删除正确的单源结论。

## 本轮真实请求与零调用复验

输入固定为 Stage8 v3 已付费生成的 core 候选：原问题、计划、候选正文和每句自己的引文。核验器没有收到金标、旧核验答案或未引用正文。新身份与旧回执隔离，预算为一次模型请求、零次业务工具、2400 输出 token、60 秒；任何已保存的失败或未知结果都不重发。

实际请求返回 1436 个输出 token、10485 个总 token，正文均使用当前合法 `ans_` ID。返回同时给三条补查缺口附带了 `reason` 说明，旧严格 schema 将其视为额外字段，因此首次请求记录仍为 `invalid_role_response`，没有改成成功。

最终接口正式允许 wire 缺口携带最多 350 字的可选说明；该字段只保留在核验审计中，展开时不进入内部工具参数或技术结论。其他未知字段仍拒绝。随后对原始 JSON 原样解析、展开和复验，未增加模型调用。

| 零调用检查 | 结果 |
|---|---|
| 原返回 JSON | 原样解析，无文字修补或字段删除 |
| 正文 ID | 全部绑定当前候选并展开为实际中文正文 |
| 来源片段复验 | 6/6 |
| 生成引用逐字一致 | 9/9 |
| 保留结论 | 8 条 |
| 内部任务覆盖 | 5/8 covered，3/8 partial |
| 最终类别 | partial |
| 新增模型 / 业务工具 | 0 / 0 |

三个部分覆盖任务为 NVD 完整受影响范围、NVD 分支首修表述与 load/loads 信任/allowlist 边界。这是内部 AI 覆盖意见，不是独立准确率。旧候选仍带有已知的“三个暴露条件”表述，当前核验模型仍可能将局部列表误判为完整；这项语义风险没有被正文 ID 修复证明消除。

原 Stage8 失败、此次首次核验失败、协议、回执和语料均保留原字节。原请求与新代码的零调用解释分别存档，不拼接成完整 Agent 成功或新的留出得分。
