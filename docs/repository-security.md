# GitHub 发布与敏感信息检查

本仓库发布源码、运行配置模板、测试和文字评测材料。本地 `.env` 保留供当前环境使用，通过 `.gitignore` 排除；`.env.example` 只提供空值或示例配置。接收方应复制模板并填入自己的密钥，不应分享实际 API 密钥、管理员密钥、数据库密码或 GitHub Token。

数据库、原文缓存、模型、会话、检查点、输出文件及私人归档留在本地，`data/`、`output/`、`release/`、`archives/`、虚拟环境和 IDE 配置不属于发布内容。文档与脚本中的个人本机路径已改为相对路径或通用示例，历史测试 XML 中的个人主机名已匿名化。公开安全公告、漏洞 PoC 和评测引文中的上游邮箱、路径、示例地址保留其原始语义。

发布前从项目根目录运行：

```sh
python3 scripts/check_repository_secrets.py
git add .
python3 scripts/check_repository_secrets.py --staged
```

脚本仅依赖 Python 标准库和 Git。默认检查已跟踪文件与未被忽略的候选文件，`--staged` 检查整个 Git 索引里的实际内容，因此能发现“工作区已删除密钥，但暂存版本仍含密钥”的情况。强制加入的本地环境文件、数据库、私钥或证书及本地产物目录会被阻止。脚本同时检查常见供应商凭证格式与私钥头，并把根目录本地 `.env*`（排除 `.env.example`）中名称含完整下划线分隔单词 `KEY`、`TOKEN`、`PASSWORD` 或 `SECRET` 的非空字面值与候选内容按完整值及文本边界比对；`MAX_TOKENS` 之类数量配置不视为凭证。输出只包含文件路径、行号和规则名称，不打印匹配到的值。退出码 `0` 表示通过，`1` 表示有发现，`2` 表示检查未能完整执行。

短于 8 字符的本地值容易与公开语料中的数字、计时、版本或普通词碰撞，因此只在名称含凭证词的配置/赋值上下文中比对，不做全库任意文本匹配；这些短值仍需人工复核。此次检查中的短值偶合来自历史测试 XML 的数字、公开冻结语料及评测数值，未据此删除公开原文或变更本地配置。

这些检查不能保证检测所有凭证或个人信息：不扫描提交历史，不解包压缩文件，不解析二进制文档，不解析 dotenv 变量插值或跨行值，也不能识别所有私有服务的自定义凭证。公开资料中的地址和邮箱不会被一概视为凭证；规则命中仍需根据上下文处理。发布前应审阅暂存文件清单与差异。若密钥已经上传，应先在供应商处撤销或轮换，再清理历史；仅删除当前文件不能移除旧提交里的密钥。

需要 ZIP 时，从审核过的提交导出：

```sh
git archive --format=zip --output=../ai-security-agent-source.zip HEAD
```

`git archive` 只打包指定提交中的文件，不包含 `.git`、未提交文件或被排除的本地检查点。ZIP 的安全性仍取决于该提交本身已经通过检查。
