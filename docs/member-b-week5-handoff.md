# 成员 B 第五周交接

交接日期：2026-09-21。目标是完成排期中的“冲突核验、动态补证、个性化推荐”，并补齐第四周未完成的真正多轮和多跳能力。

## 可使用的新能力

```http
GET /api/v1/events/{event_id}/trace
GET /api/v1/assets/{asset_id}/evidence-graph
```

事件 trace 返回全部 revision 的字段差异、原文证据复验结果和审计变化。资产 evidence graph 返回从 SBOM 组件到来源原文字段的完整链路。两者均为可重建只读派生结果，不引入新的来源事实。

## B 第五周必须完成

1. **持久多轮会话**：增加 conversation/message 数据模型；每轮保存用户问题、显式资产、选中事件、引用、约束和答案。后续轮只能使用会话内已明确选择的资产，不得通过自然语言猜资产。
2. **可视化多跳轨迹**：至少支持“CVE/公告 → 跨来源比较 → 资产 exposure → event trace → 原文证据”确定性路径；每一跳保存输入、输出和证据标识。
3. **动态补证**：遇到 unknown、资料缺口或冲突时生成补证任务，明确缺少字段、目标来源和完成条件；不能伪装成已联网验证。
4. **冲突核验**：沿用 comparison 人工复核，增加 trace 证据双栏，并保留复核前后版本和分析备注。
5. **个性化推荐**：只使用用户明确选择的资产环境、重要度和组件；输出“优先复核/升级建议”，不得把规则排序称为风险概率。

## 验收门槛

- 至少 3 组多轮用例：上下文继承、切换资产、拒绝隐式资产。
- 至少 3 组多跳用例：完整链、unknown 动态补证、severity conflict 人工复核。
- 每一跳能还原 event、revision、raw document、JSON Pointer；不能只记录自然语言过程。
- 会话重放结果确定，审计数据不依赖浏览器内存。
- 补证任务与真实联网采集分开；未执行的任务不得显示为已验证。
