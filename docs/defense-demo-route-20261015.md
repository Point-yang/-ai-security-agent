# 知盾使用与答辩演示路径

核对日期：2026-10-15。以下按钮名称和三来源案例已在当前 8010 页面实际查看；未提交新模型任务、未修改来源审核状态、未向主库导入资产。

推荐主线约6分钟：**来源监测 → 同一漏洞的三份情报 → 自动富化 → 原文与版本证据 → 来源差异 → Agent轨迹 → 会话审计**。时间是排练建议，不是比赛规定。

## 一、先准备页面

1. 打开 http://127.0.0.1:8010/workspace ，不要直接双击 `src/zhidu/static/workspace.html`。页面需通过服务访问数据接口。
2. 正式演示时将页面放到较宽的独立浏览器窗口，再点击右上角“答辩模式”。它是紧凑展示布局，不等同操作系统全屏。
3. 检查“服务已连接”、索引和来源状态。本次页面显示1289条事件、7040条向量、9/10目标新鲜；这是时点状态，演示当天以刷新结果为准。
4. 浏览情报、比较来源和查看历史回放可先不提交问答。提交新问答时，展开“授权访问与任务范围”，填写本项目管理员密钥。它对应服务端 `ZHIDU_ADMIN_KEY`，不是 DeepSeek API Key；提前填写，避免投屏展示配置文件或密钥。
5. 准备两个标签页：一个做当前查询，另一个提前在“Agent 指挥中心”点击“查看历史真实运行”，作为模型接口不稳定时的备用。历史页必须明确说是回放。

服务目前已运行，通常无需终端操作。仅在服务确实未启动且8010端口未占用时，可在项目目录执行：

```sh
cd /path/to/zhidu-intel
.venv/bin/python -m zhidu serve --host 127.0.0.1 --port 8010
```

## 二、6分钟主线

| 顺序与建议时长 | 页面与具体操作 | 展示重点与讲解句 |
|---|---|---|
| 1，40秒 | 指挥中心查看“来源新鲜度”；点击“查看采集目标与历史断档”，或打开 `/#monitoring` | “系统按目标持续采集，记录上次成功、失败和断档。API可用、采集进程健康、来源新鲜是三个不同状态。” |
| 2，40秒 | 左侧“情报与证据检索”；检索方式保持“情报列表·标题/GHSA”，其余筛选清空；在 **CVE/别名** 填 `CVE-2026-73557`，点“查询” | 本次核对返回GitHub、NVD、vLLM厂商三条记录。“同一个漏洞的不同来源分别保存，没有直接合并成一条结论。” |
| 3，50秒 | 点击标题以 `vLLM:` 开头的GitHub记录；查看“结构化摘要”和“影响组件” | 展示包实体、版本范围、修复版本、CVSS与资料质量标记。本次GitHub记录为pip/vllm、影响`>= 0.21.0, < 0.26.0`、首修`0.26.0`；这是来源声明。 |
| 4，50秒 | 在右侧“引用与证据”展开 `packages /0/vulnerabilities`；展示引用版本、原文ID、SHA-256；可点“查看该版本完整原文JSON” | “结论能追到具体来源版本与原文字段。”中间“版本对比”可选择v1/v2；本次可见来源更新时间变化，不必编造每次都有技术内容变化。 |
| 5，50秒 | 左侧“来源复核与比较”；CVE精确编号填同一个编号，点“查询比较”；查看`affected_scope` | “来源表述有差异，系统保留各自原文及版本，不自动选胜方。”下面有明确的版本差异示例。 |
| 6，90秒 | 回“Agent 指挥中心”；先看预备标签页的“历史真实运行”，展开一条结论对应原文、工具记录与完整执行审计 | 按“规划→检索补证→形成结论→引文核验”解释协作。指向模型次数、工具次数、引用复验、耗时、成本。“这是保存的真实运行，本次没有重新调用模型，也不作为当前正确率。” |
| 7，40秒 | 左侧“会话与执行审计”，选择一条已保存会话 | 展示持久会话、实际引用、动态补证任务。`pending/not_started`只表示待处理，不能说已经联网验证。历史回放按钮不会新建服务器会话。 |

最后用一句话收束：**“我们展示的是从多源资料到可追溯判断的过程，每个结论都保留来源、版本和执行记录。”**

### 已核对的来源差异

当前 `CVE-2026-73557` 的 `affected_scope` 比较显示：

| 来源 | 本地保存的原生受影响版本表述 |
|---|---|
| GitHub | `>= 0.21.0, < 0.26.0` |
| NVD affectedData | `>= 0.20.2rc0, < 0.26.0`，status为affected |
| vLLM厂商记录 | `>=0.21.0` |

这里适合展示上下界及原生字段差异，不直接宣布某个来源错误，也不根据未提供的上界补造范围。CVSS显示相同分数也可能因版本或发布方字段而标variation；variation不等于漏洞严重性冲突。

页面“跨来源版本比较”预设目前使用 `CVE-2025-24357`，本次检索仅得到GitHub和厂商两条，未见NVD记录。演示建议手动输入上面的已核对编号，不照搬该旧预设。

## 三、现场运行一次新的问答

在演示前先试运行；当前云模型链路有过超时，不把未经排练的长问题作为唯一主线。

1. “Agent 指挥中心”→“授权访问与任务范围”填管理员密钥。
2. “＋新会话”，或选择专门用于答辩的会话；不要沿用无关研究会话。
3. 在问题框粘贴下面的问题；可选“检索词”只填写 `CVE-2026-73557`，本轮不选资产。
4. **执行策略**选择“多角色规划、补查与引用核验（实验）”；**检索策略**选择“Embedding混合检索与重排”。两者是不同层次，选择“受限Agentic RAG”检索并不等于启用多角色团队。
5. 点“启动任务”。结果返回后再展示右侧角色回执及工具记录。等待时只有等待计时，不是逐角色实时进度。
6. 展开“对应原文”“问题完整性与研究记录”“查看完整执行审计JSON”，最后点“导出本轮回执”。如结果是partial，说明缺了哪项；角色返回或引用字节复验通过都不等于整题正确。

推荐短问题：

> 比较 CVE-2026-73557 在 GitHub 与 NVD 中的受影响版本范围，指出上下界差异，并逐项给出原文引用。

追问示例：

> 哪个来源明确给出了首次修复版本？请引用其原始字段，不推测未写明的信息。

这两个问题适合展示同会话追问。当前没有为本指南实际调用模型，所以不保证某次生成一定成功或完整。

### 三种执行策略怎样选

| 目的 | 执行策略 | 检索策略 |
|---|---|---|
| 不依赖云模型，展示检索与引用 | 仅本地原文摘录 | 混合；本地embedding不可用时改词项基线 |
| 展示收集证据后生成自然语言回答 | 固定工作流收集证据并回答（推荐） | 混合 |
| 展示多角色规划与动态补查 | 多角色规划、补查与引用核验（实验） | 混合 |

“仅本地原文摘录”不生成完整中文推理答案；固定工作流也不应讲成多角色自主协作。

### 超时或结果不确定时

保留原请求和回执，不连续点击“启动任务”制造新请求。根据页面提示检查原请求状态；是否重发由恢复规则决定。现场可切到预先打开的历史回放标签页，说明当前在线请求尚未完成。

历史ONNX回放来自2026-10-13真实实验：原轮5次模型请求、3次工具、5条来源、约13秒；本次回放模型调用0。页面同时注明“原实验语义仍有遗漏”，已知遗漏为未在正文完整表达不可信模型适用范围。它展示执行与审计机制，不能冒称本轮现场成功或满分正确答案。

## 四、资产影响研判：可选的加分支线

当前主库没有导入资产，直接进入“资产影响研判”会没有可选对象。这个分支需先准备隔离演示库；不要把虚构资产导入正式库后当真实资产展示。

已备好 [虚构vLLM 0.22.0 SBOM](../output/demo-route-20261015/demo-sbom.json)。隔离库准备好后：

1. 打开隔离服务的 `/assets`，选择“虚构演示资产 vLLM 0.22.0”。
2. 找到 `CVE-2026-73557` 或 `GHSA-pr7f-p5mw-fc87` 对应组件判断。
3. 展示 `affected/not_affected/unknown`、组件版本与来源条件。
4. 展开字段证据和历史变更，说明“条件匹配不是漏洞已复现”。
5. 工作台“资产影响研判”也可明确选择该资产并下载报告。

下面命令是准备说明，**本次未执行复制、资产导入或启动8031服务**。从项目根目录运行，目标文件已存在时停止，不覆盖已有演示库：

```sh
.venv/bin/python - <<'PY'
import sqlite3
from pathlib import Path
from zhidu.config import Settings
url = Settings().database_url
if not url.startswith('sqlite:///'):
    raise SystemExit('此准备步骤仅适用于当前SQLite部署')
source_path = Path(url.removeprefix('sqlite:///')).resolve()
target = Path('output/demo-route-20261015/asset-demo.sqlite').resolve()
if target.exists():
    raise SystemExit('演示库已存在，请另选目录，不覆盖')
with sqlite3.connect(source_path.as_uri() + '?mode=ro', uri=True) as source:
    with sqlite3.connect(target) as destination:
        source.backup(destination)
print('已创建隔离数据库副本')
PY

ZHIDU_DATABASE_URL=sqlite:///./output/demo-route-20261015/asset-demo.sqlite \
  .venv/bin/python -m zhidu asset-import output/demo-route-20261015/demo-sbom.json \
  --asset-name '虚构演示资产 vLLM 0.22.0' --environment demo

ZHIDU_DATABASE_URL=sqlite:///./output/demo-route-20261015/asset-demo.sqlite \
ZHIDU_LLM_PROVIDER=extractive ZHIDU_DEEPSEEK_API_KEY= ZHIDU_AGENT_MODEL_API_KEY= ZHIDU_ADMIN_KEY= \
  .venv/bin/python -m zhidu serve --host 127.0.0.1 --port 8031
```

之后访问 http://127.0.0.1:8031/assets 。此命令启动本地只读展示，不启动采集器、不配置云模型密钥，也不启用网页写操作；这不是完全断网性能测试。
