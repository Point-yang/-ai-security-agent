# DeepSeek 接入后的估分与双人完善安排

日期：2026-09-28。沿用 [上一轮评分审计](competition-score-audit-20260927.md)及赛题原文第 2–4 页权重。本轮是状态评估与后续建议，不表示以下计划已经实现。

## 结论与计分口径

内部保守估分：初赛约 **60/100**，决赛准备度约 **55/100**。相比上一轮 59/54，问答功能各暂加 1 分；它是介于既有能力和下一档之间的主观估计，不是官方规定“接 API 加 1 分”。

初赛 15 分、决赛 20 分性能指标仍待可靠证据，本次暂按 0 计入预算，不表示真实准确率为 0，也不意味着官方强制缺某种报告记 0。现场答辩没有亲历，仍只按材料准备度暂估。不能把接入一次大模型就算作自主 Agent 或准确率达标。

## 本轮实查

- 真实库仍为 672 事件、3130 检索片段及向量、37 条扩展目录；来源边界沿用既有验收，未有新的 live 覆盖证明。
- 最新持久化 RAG 记录：DeepSeek `completed`、实际模型 `deepseek-flash`、4 条引用、耗时 3801.176 ms。先前独立联调样本为 4302.750 ms，二者不能当成 P95 或一般响应时间承诺。
- 引用编号和逐字原文可校验，`semantic_support_verified=false`。是否概括正确、是否完整回答问题仍需独立判断。
- 最新回归记录 168 项通过，本轮读取其 JUnit 文件，未重复跑测；工程测试不作为问答正确率。
- A/B 两份人工审核表仍各为 0/127 已填写审核时间。
- 顶部 RAG 表单没有传递会话 ID；生成模块没有传递历史会话。旧持久会话仍走抽取式回答，不能宣称已完成大模型连续追问。
- 检索、补证、引用检查的分支仍由规则控制。DeepSeek 本次只负责基于片段生成，不选择工具，不构成新的自主规划或多 Agent 协作。

## 下一轮两人安排

独立标注和新增来源的持续监测应从第一阶段就启动，与功能开发并行；不要等新功能都完成后才开始积累评测数据。

| 阶段 | 成员 A | 成员 B | 可验收结果 |
|---|---|---|---|
| 1：把 RAG 做完整 | 检索上下文包含标题、描述、版本和修复证据；检查分块、去重、历史版本失效与来源一致性 | 把大模型接入持久会话，处理“它/这个版本”的指代与信息不足时的澄清；突出问答入口，折叠诊断信息 | 同一会话能完成“问题是什么→影响哪些版本→有何修复依据”；缺少资料时明确说明；版本结论有对应引用 |
| 2：让 Agent 做有效决策 | 为检索、事件详情、资产比较和证据复验提供明确工具契约、权限、参数验证、预算与失败返回 | 实现模型规划与工具选择；证据不足时有限次再检索；分离检索分析与证据复核职责 | 工具日志能证明按不同问题选择不同工具；一次失败可恢复或明确停止；普通 RAG 与 Agent 对照保留失败样本 |
| 3：补齐数据和评分证据 | 真实补采博客、指南/政策和 POC 元数据，建立相关性过滤与漏洞关联；持续监测并记录新增资料延迟 | 新增生成回答评测：答案正确性、引文是否支持结论、完整性、拒答、多轮、多跳及端到端延迟/费用 | 开发调优与留出测试分开；富化、问答和时效有可核查分母、样本与原始记录 |
| 4：完成交付闭环 | 告警和故障恢复闭环、实际演示机部署、创建含新代码的最终备份并恢复验证 | 更新 Word/PDF、PPT 与视频，清晰展示成功和不确定情况；组织计时答辩 | A/B 实际操作主路线和故障路线并记录，不代签，不将草案标作冻结成品 |

A/B 在以上阶段共同完成既有 127 个候选的独立审核及分歧处理。127 不是官方强制数量；若题型覆盖不足，另补版本、修复、资产、跨源冲突、资料缺失和恶意指令样本，先冻结测评标准再观察模型表现。无法裁决的分歧应保留并请第三人复核，不自动用模型答案当金标。

## 得分目标与优先级

1. **先争取性能合格档**：决赛富化准确率≥80%且召回率≥70%；问答准确率≥75%且响应≤5s；监测延迟≤24h。这些是赛题阈值，当前尚未验证同时达到。
2. **再争取优秀档**：富化准确率和召回率均≥95%；问答准确率≥95%且推理依据可解释；新增漏洞监测延迟≤6h。P50/P95、慢请求、失败和拒答单独报告，不用一次3.8秒证明全体达标。
3. **Agent 必须有收益证据**：比较“抽取式基线 / 普通大模型 RAG / Agent RAG”，使用同一留出题集；评价正确性、补证成功、引用支持、时延与费用。多角色命名或更多工具次数不是效果提升。
4. **90 分是条件预算**：只有问答与富化质量、持续监测、有效 Agent 和答辩材料同时补齐，才能重新评估是否接近 90。按当前其他项不变，即使决赛20分性能分全拿到，也只是本估分表的75分。

技术投入顺序：RAG 上下文与会话 → 有效工具决策 → 质量评测与数据覆盖。会话 memory 可以作为追问能力的必要实现；跨会话长期记忆、微调和 KV cache 暂不优先。先通过错误分析证明需要它们，再做可比较实验，不用技术名词替代得分指标。

本项目最值得继续强化的差异点是“结论能定位到具体来源版本和原文字段、来源变化使旧复核失效、资产判断保留未知条件”。将这些能力和大模型问答贯通，比单纯新增一个聊天页面更能体现实际价值。
