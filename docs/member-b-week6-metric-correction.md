# 第六周评测口径修正

独立审查指出无答案题存在高估：原实现 `not expected or event_id in expected` 使空期望集合上的事实摘录被错误计为问题支持。现在分别统计逐字原文一致性和问题相关支持；后者必须属于期望事件集合，空集合永远不支持事实摘录。零输出时支持率为 null，而非自动100%。

基于独立评测库保存的原回答重新打分，未重新生成答案，未改动原始耗时：

| 策略 | 原报告问题相关支持 | 修正结果 |
|---|---:|---:|
| lexical | 30/76 = 39.47% | 30/76 = 39.47% |
| hybrid | 42/86 = 48.84% | 32/86 = 37.21% |
| agentic | 42/86 = 48.84% | 32/86 = 37.21% |

原单并发、并发2报告原样保留。替代口径记录为 [单并发修正版](member-b-week6-rag-evaluation-corrected.json) 和 [并发2修正版](member-b-week6-rag-concurrency2-corrected.json)，每份都记录原报告摘要与自己的摘要。历史 v1 报告不再在页面作为当前有效支持率展示。

原20题准确名称为 train/development characterization：8题 train、12题 development、0题 test。按检索 query 语言分为9题英文、11题中文，其中中文包括8个正向题和3个拒答题。新报告按 split、language 分层，同时分别给出正向题数量、类别匹配和拒答比例，避免把拒答题计入中文可回答问题成功率。

原题 `case-6-zh` 与 `case-7-zh` 没有公告编号、事件 ID 或会话上下文，不能唯一选择其隐含目标；它们保留在原集合中，不改标签。新增14题挑战集另行冻结，包含12个政策拒答题和2个显式上下文版本问题，不冒充独立人工留出集。

宽泛问题可能对应多份不同公告，当前期望事件列表也可能不穷尽。例如音频解压、Mooncake 集成和视频处理各有不同来源记录。程序不能根据评测结果扩充期望标签来提高支持率；这些争议需要独立人工审核。
