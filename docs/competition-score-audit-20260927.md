# 按赛题九原评分表的当前估分

评估日期：2026-09-27。依据赛题原 PDF 第 2–4 页初赛、决赛评分参考表；代码、真实数据库和最新 B 第八周交付材料均已检查。只作内部备赛估分，不代表组委会评分。

## 计分口径

- 功能和工程项按已实现能力作判断；主观项目的分数属于评估者估计，不是官方固定扣分公式。
- 尚未证明数值门槛的性能项标为“待验”，本次保守预算暂按 0 计入总数。这不表示实际准确率为 0，也不是赛题规定“没有某种报告就记 0”。赛题没有强制 127 题或双人标注；这些是项目自己选择的可信评测流程。
- 演示项按现有材料准备度暂估 6 分，没有实际观察两名成员的现场答辩，不能称为实际答辩成绩。
- 不能把 5 个适配器算成 5 类来源，不能把元数据回放算作连续在线覆盖，不能把引文哈希一致率换成答案准确率。
- 赛题没有要求必须使用某家大模型、某个 Agent 框架、微调、memory 或 KV cache。未接入生成大模型本身不是自动扣分条款；当前复杂语义分析、自主决策和多角色编排不足才是相关失分原因。

## 现状证据

本轮只读查库：672 事件、802 版本、118 原文、3130 片段与向量；37 条扩展目录全部为 replay。A/B 两份审核表各有 127 个候选，已填审核时间均为 0。

当前 RAG 代码仍为 `extractive-packet-v4`：本地 embedding 检索、确定性工具分支、来源片段输出，没有生成模型调用。五跳轨迹主要表达证据关联，不能直接等同开放问题的多跳推理正确率。

B 2026-09-27 新交付包含 6 页报告 Word/PDF、12 页 PPT/PDF、82 秒真实界面截图分段视频和一页流程；已读取报告全文并检查页面。报告当前偏概要，正式技术报告仍需补设计图、工作流程图、核心代码说明及各模块实现效果。152 项测试通过来自本轮核查的最新 JUnit 文件，非本次重新跑测。

开发评测原 20 题为 8 train / 12 development：混合与受限 Agentic 类别匹配 90%、相关支持 67.57%、中文正向 Recall@5 为 75%。这些口径都不等于总体答案准确率；Agentic 尚未在该组题上证明质量增益。最新补交仍说明来源超期和长期监测缺口，未找到新的 SLA 达标证据。

## 决赛 90 分目标预算（需逐项证明）

| 项目 | 目标分 | 达成条件 |
|---|---:|---|
| 监测完整性 | 10 | 缺失类别真实采集与持续更新、增量去重，扩展目录接入可用知识链路 |
| 富化完整性 | 9 | 论文/文章/POC 元数据与具体漏洞可靠关联，缺失与不确定状态明确 |
| 问答完整性 | 9 | 完成基于证据的大模型 RAG，复杂查询、跨文档解释与显式资产建议可演示 |
| 监测时效与稳定性 | 5 | 持续采集窗口证明新增资料发现延迟≤6h，记录断档与故障恢复 |
| 富化准确率与召回率 | 5 | 代表性标注集上两者均≥95%，明确分母和匹配规则 |
| 问答质量 | 10 | 独立题集准确率≥95%、推理依据可解释；保留完整端到端响应时间统计 |
| Agent 运用 | 12 | 有效多角色协作与自主工具编排，失败可处理，保留工具日志与对照实验 |
| 工程化 | 9 | 当前基础上补持续监测告警和自动恢复闭环，实测部署设备 |
| 文档 | 9 | 报告满足原文内容要求，图示、实验、失败分析和匿名格式完整 |
| 答辩 | 8 | 两人真实计时排练、能回答基础与深入追问，备用方案可切换 |
| 创新与实用 | 4 | 用案例和对照证明证据链与资产工作流的实际价值 |
| **目标** | **90** | 条件预算，不保证获奖；最高奖项还取决于同场作品及评委 |

优先顺序：大模型 RAG 与有效 Agent 决策链 → 与之并行的标注和测评 → 缺失来源与持续监测 → 报告及联合答辩。微调、memory、KV cache 没有独立加分栏，只有改善上述指标才值得投入。
